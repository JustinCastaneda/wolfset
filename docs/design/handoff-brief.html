WOLFSET · HANDOFF BRIEF
What the Figma and the flowchart don't say

The Figma carries the screens. The flowchart carries the edges between them. The build plan carries the order of work. This page carries the third thing a coding agent needs and none of those three hold: the rules that decide what a screen does when a condition is met, and the list of things that are deliberately not designed yet. Read it alongside the flowchart, not instead of it.

READ THIS FIRST
The product is WOLFSET. The design files say Gym Wolf.

Both names are in circulation across the material being handed over: the Figma file is Gym Wolf Application.fig, the flowchart is titled Gym Wolf, and the build plan locks WOLFSET while explicitly rejecting Gym Wolf for cause. WOLFSET wins. Treat every in-file occurrence of Gym Wolf as a stale label, not a second product, and do not carry it into identifiers, package names, string tables or the splash wordmark. The wordmark treatment is locked: WOLF in red, SET in white.
01 · THE SET LOOP
One state machine, five screens, six transitions

This is the centre of the app and the part most likely to be built wrong from the screens alone, because half of its transitions are conditions rather than taps. Every exit below is a real transition in the flowchart.

Log a Set → Post Set Timer
User logs the set. The timer starts on its own; it is not a screen the user chooses to visit.
Post Set Timer → Log a Set
Two triggers, one destination. The countdown reaches 0:00, or the user taps Continue before it does. Either way the next set of the same exercise loads. Do not build these as different paths.
sets exhausted → next lift
Inside a mesocycle the loop above repeats until the exercise's prescribed sets are used up, then the next exercise in the day takes over and the loop restarts against it. Same screens, new exercise.
last lift done → Workout Summary
Workout Summary is the running list, reachable during the session. It is not the end of the session.
Finish → Session Done → tiles
Finish always lands on Session Done, and Session Done always returns to the opening tiles. True on the phone and on the watch. Session Done's secondary exits — Add to Plan, New MesoCycle — re-enter plan build instead.
Log a Set ↔ Edit Weights
Tap the weight to open, save to return. A detour off the loop, not a step in it. Freestyle sets are open-ended, so “sets exhausted” has no meaning there — the loop only ends when the user ends it.
02 · RULES BEHIND THE SCREENS
Numbers that exist in conversation only
PROGRESSION
Hit every rep → +3 reps. Missed → drop 10%.

The default rule the app applies between sessions, shown as the Progression Override screen in plan build. It is per-exercise and set at the time the exercise is added, so the storage model needs a per-exercise override field, not one global setting.

PACING
Rest is per exercise, not per plan

A deadlift needs longer rest than a curl, and the user knows that while adding the exercise. Pacing is therefore settable in two places: at Add Exercise Details during plan build, and as a settings detour off Workout A (1:30 rest, auto-start timer). Same field, two entry points.

WEIGHT ENTRY
Custom keypad, not the OS keyboard

+5 and −5 cover most edits; the keypad is for the rest. Built rather than borrowed because the OS number pad's keys are too small for gym use, it eats the screen the set row needs, and it can't host the increment buttons. Numeric only, 44px minimum targets.

HEART RATE GATE · NEEDS A NUMBER
Red → yellow → green, thresholds undefined

The timer screens show 168 red, 145 yellow, recovered green on the phone; 168, 142, 122 on the watch. Those are illustrative values in a design file, not a rule. What counts as recovered — an absolute BPM, a percentage of the session peak, a return toward resting rate — is undecided and Phase 0 is where it gets decided.

03 · SHARED SCREENS
Drawn twice in Figma, built once

The Figma has around 50 frames because journeys were drawn end to end and the shared middle got redrawn each time. Building frame-for-frame would produce several copies of the same screen that then drift apart.

Log a Set
One screen. Plan and freestyle both land on it.
Edit Weights
Three frames in the file. One screen with +5, −5 and keypad states.
Post Set Timer
Three heart-rate frames, two of them still named Android Compact – 2 and – 3. One screen, three states.
Workout Summary
One screen. Its title is Freestyle or Workout A depending on how the session started — the only difference.
Getting Started
Also serves as Create New MesoCycle. Same flow, second entry point: the Change It Up hub, reachable mid-cycle. The plan lists them as separate line items in Phase 5; they are one build.
Confirm Email Timer
Drawn four times across two journeys. One screen with a cooldown state.
04 · NOT DESIGNED YET
Stop and ask rather than invent

Three known gaps. Each has an agreed behaviour and no frames. An agent that fills them in from pattern memory will produce screens that have to be thrown away.

GAP
Preset plan review

Picking a preset from Select a Plan drops the user at the end of plan build: the whole workout as a summary. Accept takes it as-is; clicking any row puts them in the same editors someone who built it by hand would use. Blocked on the plans themselves. The first preset will be a 5×5, usable as the reference case.

GAP
Watch weight adjust

The watch set screen has two swipe panels. Left is Actions — Skip Set, Change, End — and is drawn. Up adjusts the weight, does the same job as the phone's Edit Weights, and is missing from the file. Same rules, watch-sized UI.

GAP
Editing a live plan

Starting a new mesocycle mid-cycle is covered. Changing an exercise inside a plan that is already running, without starting over, is not drawn anywhere and the flowchart has no edge for it.

05 · WHAT THIS ADDS TO THE PLAN
Five things worth folding in
Phase 1 · flowchart
Mark it done. The flowchart resolves the five edges it originally flagged as inference; two of them now point at gaps in the Figma rather than gaps in the graph.
Phase 1 · data model
Progression and pacing are both per-exercise overrides with a plan-level default. That shape needs deciding before the schema, not after.
Phase 0 · exit criteria
Add one: come out of the spike with a definition of recovered. Live BPM on the phone proves the pipe works, but the gate can't ship without a threshold rule.
Phase 3c · components
The keypad is a component, and it is on the workout path. It isn't in either component list.
Phase 5 · ordering
Create New MesoCycle folds into Getting Started. Freestyle needs the shared engine to handle open-ended sets, so build it after Set Workflow, which the current order already does.
